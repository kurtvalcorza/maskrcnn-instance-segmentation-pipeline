## Conformance notes

- **Standalone carrier (§4):** the default path performs no clone, repository install or repository import. Section 2 carries `samples.py` and `pipeline.py` verbatim in dependency order (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative). Section 3 carries the model identity and the manifest inline and asserts that they agree with the module before anything is fetched. Section 1 carries the exact `pyproject.toml` runtime pins and the hash-locked `tutorials/requirements-colab.lock.txt` (33 packages, every version and hash equal to the lock of `detr-detection-pipeline` c3c81cb, which passed a one-pass Colab T4 Run all); it builds a uv environment with a managed CPython 3.12.12 (`--require-hashes --only-binary :all:`) and routes every later cell to it, so nothing is installed into the kernel and no restart is needed. Linux x86_64 only.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried module, the inline manifest or the inline pins differ from the repository, or when the notebook differs from the generator's output.
- **Model acquisition (MOD1–MOD8):** the checkpoint is pinned to the SHA-256 of its bytes (the three loaders would raise before any download if `MODEL_REVISION` were reset to `"unpinned"`). `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches the checkpoint only from the manifest URL on download.pytorch.org, `verify_snapshot` checks its byte size and SHA-256, and `from_pretrained(weights_dir=WEIGHTS_DIR)` builds the architecture with `weights=None` and loads the verified file with `torch.load(..., weights_only=True)` and `load_state_dict(strict=True)`.
- **Stages:** `validate_inputs` writes the input manifest, including one rejection finding from the `threshold=1.5` probe; `evaluation_report` writes the single-image `sample-sanity` report; `validate_dataset` validates the adaptation records; `evaluate` computes box and mask AP before and after `finetune`; `save_artifact` writes `outputs/maskrcnn_adapter.safetensors`; `load_artifact` rebuilds from the verified base and the adapter, and the notebook compares boxes and scores within a stated tolerance and masks by a stated minimum IoU.
- **Scores (UNC1–UNC4):** every `score` is a softmax class probability after torchvision's per-class NMS, not a calibration for the reader's images; `MASK_THRESHOLD` (0.5) binarises each mask. `threshold` is a `# @param` field passed explicitly on every `detect` call.
- **Non-interactive execution (EXE1–EXE5):** seeds, schedule, threshold, BYOD switches and BYOD locations are form fields (every schedule field in the Section 8 cell); outputs go to `outputs/` under the working directory. `DIMER_NOTEBOOK_CI_PREINSTALLED=1` (an executor that pre-installed the pins) and `DIMER_ISOLATED_ENV` (the environment folder) are documented in the notebook's How to use.
- **Guided layer (GDL1–GDL14):** audience, Input → Model → Output, How to use, roadmap, observable learning objectives, a prediction before each of Sections 4–11 with a collapsible worked answer from a recorded run, the Section 14 change-one-thing activity (unfreeze the backbone; Section 8 re-runs start from the re-headed model via `reset_to_pretrained()`), troubleshooting, glossary and a conclusion template; Sections 1–3 labelled Infrastructure with the carried modules collapsed. The saturated 1.0 rows are named and explained in Section 9 (task at its ceiling); the activity compares box AP@[.50:.95].
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
