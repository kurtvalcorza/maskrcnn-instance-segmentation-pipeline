# Weight provenance and hosting

- Upstream: `torchvision/maskrcnn_resnet50_fpn_v2`, meaning torchvision's `maskrcnn_resnet50_fpn_v2` builder with `MaskRCNN_ResNet50_FPN_V2_Weights.COCO_V1`. This identifier names the torchvision weights; it is not a Hugging Face Hub repository.
- Revision: `73cbd0190fcbe3ba339921fbce2c3a0b6bb9126c9a133c85e43a2a8e060a109e`. A file served from a URL has no commit, so the pinned revision is the SHA-256 of the checkpoint's bytes. `python tools/pin_snapshot.py` pinned it on 2026-09-25: it downloaded the file, checked that its SHA-256 starts with `73cbd019` (the prefix torchvision puts in the file name), strict-loaded it into the architecture, and wrote the digest and byte size into the manifest and `src/maskrcnn_instance_segmentation_pipeline/pipeline.py`.
- Source URL: `https://download.pytorch.org/models/maskrcnn_resnet50_fpn_v2_coco-73cbd019.pth`, the `url` of the weights enum in the pinned `torchvision==0.29.0`; a test asserts the two agree.
- Weight format: a PyTorch `state_dict` saved with `torch.save` (`.pth`, a zip archive holding pickled tensor metadata). torchvision's weight metadata lists its size as 177.219 MB; the pinned file is 185,828,065 bytes.
- Manifest: `weights/maskrcnn-resnet50-fpn-v2/dimer-base-manifest.json`, format `dimer_url_snapshot`, one entry with `path`, `url`, `bytes` and `sha256`. The entry carries its byte size and SHA-256, and `totalBytes` is 185828065.
- Upstream licence: torchvision's code is BSD-3-Clause. torchvision's README states that its pre-trained models may have their own licences or terms derived from the dataset used for training, and that the user must determine whether they have permission to use a model for their use case. The weights were fitted to COCO, whose annotations are CC BY 4.0 and whose images remain under their Flickr licences.
- Hosting: the Git repository vendors neither the checkpoint nor its conversion (`weights/**/*.pth` and `weights/**/*.safetensors` are git-ignored). A fresh clone stages the checkpoint from the URL above and converts it on first load.
- Fresh clone: `stage_missing_files(allow_download=True)` fetches the file only if it is absent, only from the manifest URL, and only if that URL equals the package's `WEIGHTS_URL`; `torch.hub.download_url_to_file` checks the file-name prefix during the download, and `verify_snapshot()` then checks the full SHA-256 and the byte size before any load.
- Served format: safetensors. `convert_checkpoint` reads the verified `.pth` once with `torch.load(<verified file>, map_location="cpu", weights_only=True)` (which restricts unpickling to tensors and plain containers), requires a flat dict of tensors that strict-loads into the architecture, clones every tensor into contiguous CPU storage and writes `maskrcnn_resnet50_fpn_v2_coco-73cbd019.safetensors` with `safetensors.torch.save_file` and the one-key metadata `{"format": "pt"}`. The result must hash to the pinned `CONVERTED_SHA256` `690c9bb4d92115f5e5d378a6b4d2df1c23cc25d2f9aa47ff4e690d3cdb8ba211` (185,728,244 bytes, 432 tensors), or it is deleted and the conversion refused. The conversion is byte-reproducible: two conversions on 2026-10-24 gave the same digest.
- Loader trust boundary: `maskrcnn_resnet50_fpn_v2(weights=None, weights_backbone=None, num_classes=91)` builds the architecture without downloading anything; `verify_converted` checks the safetensors digest and `load_state_dict(load_file(<conversion>), strict=True)` refuses a missing, unexpected or mis-shaped tensor. The serving path never calls `torch.load`; once the conversion exists the `.pth` is not needed.
- Equivalence (2026-10-24, CPU, torch 2.14.0, torchvision 0.29.0): every one of the 432 converted tensors equals its source tensor, and on the tutorial COCO scene the model loaded from the conversion and the model loaded from the `.pth` with `weights_only=True` returned identical `boxes`, `labels`, `scores` and `masks` (`torch.equal`; stop sign 0.9995, clock 0.9969, traffic light 0.9953).
